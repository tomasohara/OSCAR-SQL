# Combine Similar Machines — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new "Combine similar machines" preference that, when enabled, merges adjacent days in the *Changes to Device Settings* (rxchanges) report whenever they share the same brand + mode + pressure + pressure relief, and renders the Device column as brand only.

**Architecture:** Pure additive change. New boolean preference (`STR_AS_CombineSimilarMachines`, default false) stored via `AppSetting`. New `QCheckBox` in the Appearance / Other Visual Settings group of `preferencesdialog.ui`. The merge predicate in `Statistics::updateRXChanges()` is widened from `rx.machine == mach` to `rx.machine->brand() == mach->brand()` when the preference is on. The Device column rendering in `Statistics::GenerateRXChanges()` switches to `rx.machine->brand()` when on. Cache (`RXChanges.cache`) is invalidated by file deletion on toggle, reusing the existing pattern from `mainwindow.cpp`.

**Tech Stack:** Qt 6, C++17, QtCreator (developer-driven incremental builds — no automated UI tests). Spec: `Notes/2026-05-17-combine-similar-machines-design.md`.


  Add a small helper **immediately before** the `// Clear loaded rx cache` comment. This declares the toggle once and a lambda that encodes the brand-vs-pointer predicate for the rest of the function:

  ```cpp
      // Whether to merge adjacent days from different machine objects when they share a brand.
      // When false, behaviour matches the historical rule: same Machine* required.
      const bool combineByBrand = AppSetting->combineSimilarMachines();
      auto sameDevice = [combineByBrand](Machine *a, Machine *b) {
          if (a == nullptr || b == nullptr) return false;
          return combineByBrand ? (a->brand() == b->brand()) : (a == b);
      };

  ```

## Task 6: Manual verification (UI golden path)

This task verifies all four combinations of the two checkboxes against a real profile in QtCreator's debug build. **Required because OSCAR does not have automated UI tests.**

Pre-conditions:
- A test profile loaded that has at least one CPAP machine. Ideally two CPAP machines of the **same brand** with overlapping date ranges and identical mode/pressure/relief on at least one day pair, so the brand-combining behaviour is observable. (If you don't have such a profile, the toggle should still be testable — it just won't visibly merge anything.)

- [ ] **Step 6.1:** Run the app from QtCreator (F5). Open the test profile. Navigate to **Statistics** tab. Scroll to the *Changes to Device Settings* section. Note the current row count for the visible date range.

- [ ] **Step 6.2:** Open **File → Preferences** (or the platform equivalent). Go to the **Appearance** tab. Locate the *Other Visual Settings* group. **Verify** that a new checkbox labelled `Combine similar machines` appears **immediately above** `Include Serial Number`. Hover the new checkbox; **verify** the tooltip reads `Combine machines with same capabilities in Changes to Device Settings report`. **Verify** the checkbox is unchecked by default.

- [ ] **Step 6.3:** With both `Combine similar machines` and `Include Serial Number` unchecked, click **OK**. Go to Statistics. **Verify** the Device column shows `model (modelnumber)` for each row — i.e., unchanged from pre-feature behaviour.

- [ ] **Step 6.4:** Open Preferences → Appearance. Tick **only** `Include Serial Number`. Click OK. **Verify** the Device column now shows `model (modelnumber) [serial]` — unchanged behaviour for this combination.

- [ ] **Step 6.5:** Open Preferences → Appearance. Untick `Include Serial Number`, tick **`Combine similar machines`**. Click OK. **Verify**:
  - The rxchanges report regenerated (a progress bar may flash with title `Updating Statistics cache`).
  - The Device column now shows the **brand only** (e.g. `ResMed`), with no model, modelnumber, or serial.
  - On a profile with two same-brand machines spanning adjacent days with identical therapy settings: the number of rows in the report should be **less than or equal to** the count from Step 6.3 (rows that previously split because of a machine swap now merge).

- [ ] **Step 6.6:** Open Preferences → Appearance. With `Combine similar machines` still on, also tick `Include Serial Number`. Click OK. **Verify** the Device column **still shows brand only** — Include Serial is silently ignored when Combine is on, per spec.

- [ ] **Step 6.7:** Open Preferences → Appearance. Untick `Combine similar machines` (leave `Include Serial Number` ticked). Click OK. **Verify** the Device column reverts to `model (modelnumber) [serial]` and the row count returns to what it was in Step 6.4.

- [ ] **Step 6.8:** Cache-invalidation spot-check: With `Combine similar machines` toggled in one of the previous steps, the file `<profile data folder>/RXChanges.cache` should have been deleted and rewritten with fresh content. (Optional: confirm the file's modified-time updated during the OK click that toggled the value.)

- [ ] **Step 6.9:** Restart OSCAR. Re-open the profile. Re-open Preferences → Appearance. **Verify** the `Combine similar machines` checkbox retains its last value — the preference is persisted.

If any step fails, fix the underlying bug **before** Task 7. Do not patch around verification failures.
